PicoID - Changelog
==================

1.18
- The Share dialog's X works. Root cause of both close-button reports: the
  invisible full-width TITLE DRAG STRIP (mouse-enabled, for moving the
  dialog) overlapped the close button and ate its clicks. The "hitbox
  slightly to the right" feeling in 1.16 was the thin right-edge sliver the
  strip did not cover - and 1.17's hit-rect fix, aimed at the wrong cause,
  clipped away exactly that sliver and killed the button completely. Now the
  drag strip ends well short of the corner, the close button sits on a
  higher frame level so nothing mouse-enabled can cover it again, and the
  1.17 insets are removed - the X behaves like every other WoW dialog's.
  (You can still drag the dialog by the rest of its title area.)

1.17
- PICO2 strings: the section separator changed from "|" to "/". In-game
  testing proved the client DOUBLES raw pipes to "||" when text is pasted
  into an editbox (anti escape-injection) and renders them back as single
  "|" - so a pasted string looked untouched while its bytes had changed,
  and the checksum correctly refused it. This broke copy-paste import of
  every multi-item string since 1.15 (single-item strings have no pipe;
  direct send never touches an editbox and was immune). New strings start
  "PICO2:"; the parser still accepts PICO1, and a failed PICO1 checksum
  gets one "||"->"|" un-mangling retry - old strings saved in Discord now
  import fine. NOTE: 1.16 cannot read PICO2 strings, so for direct sending
  BOTH sides should update to 1.17.
- The direct-send name box is now findable: tooltip-style border plus a
  grey "character name..." placeholder that clears when you click into it.
  (It was a borderless transparent rectangle on a dark dialog.)
- The Share dialog's close button hitbox sat noticeably right of the
  visible X (transparent padding in the stock button art); the clickable
  area now matches the glyph.

1.16
- Direct in-game sharing, approved by the server owner: the Share dialog gains
  a "send to player" row - type an online player's name, press Send, and your
  PICO string travels to their PicoID over addon whispers on the client-owned
  "PICO" prefix. They get ONE clickable "[<You>'s PicoID - click to view]"
  chat line; clicking it opens the same read-only viewer as a pasted string.
  Nothing ever opens by itself, incoming text is never executed, and an
  "Accept shares sent directly by other players" option (Interface -> AddOns
  -> PicoID, default on) drops incoming shares entirely - which matters
  because addon whispers bypass the game's normal ignore list.
- The admin's safety limits, hard-coded: explicit button only, no automatic
  retry, one transfer at a time, 0.5s between parts, 3s between sends, 10s
  between sends to the same player; the whole string is capped at 900 bytes /
  4 parts / 240 bytes per message, and an oversized list is refused before
  anything is sent (the copy-paste string has no cap and stays the fallback
  for huge gear sets). Receiving side: one assembly per sender expiring after
  10s, a fresh first part replaces an unfinished one, contradictory totals /
  out-of-range or duplicate parts / excess bytes discard it, concurrent
  assemblies are bounded, and the checksum plus a bounded numeric parse must
  pass before the chat line appears. Notifications cap at one per sender per
  10s and six per minute (the list itself is still received - only the extra
  line is skipped). PICO whispers cost zero AddonThrottle tokens - the
  ICINV / USPELLDMG budget is untouched.
- Honest delivery reporting: this realm has no addon delivery receipt, so the
  sender is told "sent - delivery unconfirmed", never "delivered". The one
  explicit signal that exists - the client's own "No player named X is
  currently playing" line - aborts the transfer and is surfaced as exactly
  that. The chat line also notes when a received list's embedded owner name
  differs from the player who actually sent it.
- Scaling-note relabel (admin clarification): the hover's spell power /
  attack power percentages are the server's rounded MAXIMA of explicit bonus
  data (collected to trigger depth 2) - not complete effective coefficients.
  Overrides, DBC fallbacks, player-specific modifiers and forge potency are
  not included, and the SP and AP figures can come from different
  sub-effects. The tooltip now says "up to N% ... (explicit data - actual
  scaling can differ)", and a zero - which only means "no explicit row", not
  "no scaling" - is hidden instead of being presented as "nothing else
  scales it either".
- Bounded parsing hardening on ALL strings, pasted ones included: per-field
  digit caps, a real equipment-slot range check, and an overall length
  ceiling. Every legitimate 1.15 string parses unchanged.

1.15
- PICO share strings: the new Share button (top bar) builds a compact
  "PICO1:..." string of your equipped procs to copy and paste anywhere;
  pasting a friend's string into the same dialog and pressing View opens a
  read-only popup of their procs - names, origins, drop sources and duplicate
  highlighting rebuilt from your own local PicoID Data tables. Entirely
  offline: nothing is ever sent on the addon pipe, so the server throttle is
  untouched. Strings are version-tagged and checksummed - a chat-truncated or
  mangled paste is detected and named instead of showing half a gear set.
  (Direct addon-to-addon delivery is deliberately not included; it needs the
  server admin's sign-off on player-to-player addon traffic first.)
- Icons: the Item, Imprinted proc and Item of origin columns now show their
  icons at the left of the text. Origin icons come from ICIPROCSRC, a verb the
  server has been sending in the ICINV stream all along (the sole item
  carrying the proc, sent only when unambiguous) that PicoID previously
  ignored -- multi-source procs stay text-only by design. Origin ids ride the
  PICO string too, so shared lists show them as well.
- Hover now shows the proc's full effect -- damage AND healing, hybrids show
  both -- with its numbers rewritten to the imprinted soulforge magnitude,
  exactly the way the Dashboard's extraction window previews a proc (stock
  description x server-sent base values x magnitude; fully client-side).
- Hover also states the proc's scaling coefficients, from the ICIPROCFACT
  facts the server already sends per proc: whether ranks raise it, and the
  spell power / attack power percentages it scales with.
- Sortable columns: click a header to sort by it, again to reverse, a third
  time to restore gear order.
- Filter box (bottom-right): typing narrows the list live, matching any
  column. Esc clears it. Totals still describe the full gear set.
- Shift-click a row to insert just the proc ID into an open chat box
  (plain click still inserts "[Proc Name] (ID)").
- First user manual (MANUAL.txt).
- Window title shortened to make room for the Share button.

1.14
- Server-throttle rework (by the server admin, adopted as the live baseline):
  * USPELLDMG damage is fetched once, on hover, for the hovered proc only, with a
    6s timeout that clears the "asked" flag but never re-sends on its own. The old
    twice-a-second retry pump (which overran the per-account token bucket) is gone.
  * The prefetch that fired at login and on every gear change (window closed) is removed.
  * ICINV is debounced to one request per 10s (it costs 6 tokens on the pipe).
  * The 810 KB proc/drop tables moved to a separate LoadOnDemand addon, PicoIDData,
    pulled in by EnsureData() on first use, so players who never open the window
    never parse them. PicoIDData must stay force-enabled in the launcher manifest.
  * The USPELLDMGR tooltip repaint now requires PicoID's own row tag, so it can no
    longer overwrite Uncapped's item tooltips.
  * The empty-state message now asks UncappedThrottle and reports a dropped request.
- Author corrected to Mhortai.
